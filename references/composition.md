# Composition

Decide where attention belongs before choosing decoration.

For concrete palettes, font roles, layout seeds and chart-selection recipes,
read [Design directions](design-directions.md) and query one matching profile.

## A direction that belongs to the subject

Find a concrete property of the subject that can shape the interface: the
precision of a measuring instrument, the pace of a performance, the grain of
a material, the way a collection is organized. Translate that property into
layout or behavior. A palette name alone is not a visual direction.

For an existing brand, use its recognizable relationships: proportions,
image treatment, type contrast, or rhythm. Adding a new font and color to
every redesign can erase the identity the user wanted to improve.

Use references to identify a principle, then design for the actual content.
Do not reproduce a reference's artwork, logo, or distinctive composition
without the rights and direction to do so.

## Compose with the real content

Start with the longest credible title, an actual image crop, and a plausible
amount of supporting text. Establish a reading order with those materials.
An empty card grid reveals little about whether the finished screen works.

Give each region a job. Compare regions by their importance and frequency
of use before assigning area. A daily action can deserve more reachability
than an impressive but rarely used statistic.

Let proximity explain relationships. Before adding another box, border, or
background, check whether alignment and spacing can express the grouping.
Use containers when they clarify a boundary, selection, or interaction.

At a narrow width, reconsider order and grouping. Keep the primary task,
current state, and next action understandable without the desktop arrangement.
Use intermediate widths to locate the point where the composition stops working.

## Type and color as a working system

Choose a reading face for the actual language and content length. Check
punctuation, numerals, weight availability, and fallback behavior before
adding a display face. Separate text roles through size, spacing, and weight
before expanding the font collection.

Test the hierarchy on an unstyled content sample: title, paragraph, label,
number, error, and dense row. If every role needs an exception, simplify the
roles rather than scattering overrides.

Assign colors by meaning: canvas, surface, text, secondary text, boundary,
action, and feedback. Distinguish status using words or symbols as well as
color. Examine the actual foreground/background pair in each state.

A dramatic palette can coexist with quiet controls. Reserve the strongest
contrast for information or actions that deserve attention.

## Numbers, icons, and comparisons

A chart should answer a named question: change over time, distribution,
ranking, proportion, or relationship. Choose an encoding suited to that
question. State units, time coverage, and missing values. Use a table or a
direct number when a chart adds interpretation without useful information.

For comparison, align the attributes that affect the decision. Keep definitions
and exceptions close enough that the viewer does not need to memorize them.
Distinguish zero from unavailable and old data from current data.

Choose one compatible icon language. Use a text label when the action is
ambiguous; the same symbol can mean different things in different products.
Match optical weight and baseline, not only the nominal pixel size.

## Evaluate the direction

At normal viewing size, can somebody identify the product, its current state,
and its next action? Does the strongest visual element support that reading?
At phone size, do the same relationships still hold? Revise the element that
disrupts those answers rather than applying a blanket style rule.
